# 会话跨 Tab 连续性

状态：Review。最后更新：2026-09-15。

关联：[设计系统](../02-design/design-system.md)、[业务规则](../01-requirements/business-rules.md)、[测试计划](test-plan.md)。

## 已批准交互

用户于 2026-09-15 确认交互示意图并授权实施：会话生成回复、等待审批或等待回答时可以切换到文章及其他工作区；顶部 Tiny Note 标签保留返回当前会话的入口，显示“生成中”“待确认”“待回答”等状态。审批在会话消息区域展示，批准或拒绝必须由用户显式执行。

此调整解决全屏审批遮罩阻挡导航、离开会话丢失页面内状态，以及新建会话的慢响应强制跳回聊天的问题。文章修改继续遵循既有服务端工具和提案规则，切换页面不构成批准，也不将普通聊天加入任务中心。

## 实现边界

- 应用只缓存当前 ChatView 实例。Pinia 保存返回入口和状态；消息、草稿、模型选择、引用、待审批与待回答内容保留在账号范围内的页面实例中。
- 切到其他工作区不销毁该实例、不关闭实时连接；后台事件继续更新会话，完成后清除“生成中”。返回阅读历史消息时保持位置，原本跟随最新消息的阅读方式继续跟随末尾。
- 只处理 `/chat` 的会话查询参数；文章或日历自己的 `id` 不触发加载会话。创建成功后仅在仍处于聊天路由时更新 URL，隐藏页面只更新返回入口。
- 提交消息时立即锁定本次提交，防止重复请求；保存完成只清空实际提交的草稿，不覆盖用户随后输入的新内容。
- 审批区域展示操作说明和可展开的完整参数，保留参数哈希与运行、工具调用标识的绑定。确认按钮提交中禁用；失败时保留审批并允许重试。成功后显示已批准或已拒绝。
- 退出账号、会话失效、切换账号时同步使保留实例失效，随后销毁页面和连接。已释放的事件通道不能被慢请求或审批响应重新连接；结束订阅不被误报成模型失败。
- 1024px 最小窗口下压缩标签宽度，避免状态文字与窗口控制按钮重叠。

保留范围是本次应用运行中的当前会话；整页刷新、关闭应用、显式新建或切换历史会话后的内存草稿恢复不在此次范围内。服务端持久化消息和后台任务保持原有规则。本文不新增离线存储或浏览器凭据保存。

## 验证

先运行新增回归并确认失败，再实施修复。自动化覆盖：

- 普通空闲会话逐个切换顶部工作区，再返回同一会话，消息、草稿、DOM 和阅读位置保留。
- 生成中进入带独立 `id` 的文章路由，后台完成后返回可见新回复；不重复启动生成。
- 审批位于消息区域，离开后不会盖住文章或自动批准；返回后显式批准携带原参数哈希。
- 慢创建响应不抢回路由；保存期间再次提交不会产生重复消息，也不清空新输入的草稿。
- 阅读历史位置不会被前台或后台新增文本强行滚动。
- 待回答卡片与返回状态保留。
- 退出时阻止未完成初始化、旧事件和慢请求继续写回或重开连接。

浏览器验证使用隔离的本机样例适配器和真实 Vue 组件，不调用生产模型、账号或业务数据。已检查 1024×700 的明暗主题与 1280×800 桌面布局；实际点击会话/文章切换，检查草稿保留、审批状态及导航按钮无覆盖。最小窗口下末尾标签右边界约为 807px，窗口按钮起点为 908px，没有重叠。生成期间文章页实际显示“生成中”，会话组件未显示、无审批遮罩；返回后可见完整回复，完成状态清除，未发送草稿保留。浏览器控制台未记录到错误或警告。截图存于本机 `output/chat-navigation-qa/`。
