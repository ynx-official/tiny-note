# 大库分页与正文加载验收

状态：实施中，2026-09-06。分页接口、主笔记树、正文缓存、标签页及其余引用选择器已接入。真实桌面千篇/万篇交互与内存验收尚未执行。

## 接口

`note_page` 对应 `GET /notes/page`。默认 80 条，最大 200 条；支持 search、deleted、pinned、notebookId、knowledgeBaseId、tagId、excludeTagId、untagged 及 cursor。互斥标签筛选不能组合。普通业务错误沿用 `{code,msg,data}`，调用方同时检查 HTTP 状态与业务 code。

结果为 `{items,total,hasMore,nextCursor,notebookCounts?}`。每个摘要仅有 ID、所属笔记本/知识库、标题、200 字 excerpt、置顶、版本及时间，不含 contentHtml/contentText/contentMarkdown。SQL 投影直接截取短摘要，MySQL 客户端不读取完整正文。正文继续使用 `note_get` / `GET /notes/{id}`。

顺序为 pinned DESC、update_time DESC、id DESC；游标保存数据库时间精度，绑定当前用户及筛选条件。下一页可调整条数但不能改变筛选。首屏返回当前筛选的笔记本数量，用于树视图计数。列表不是数据库快照：翻页期间发生笔记编辑、置顶或移动时，应刷新列表以取得最新位置；客户端按 ID 去重。

旧 `note_list` 保持兼容契约；生产界面的目录和引用选择器均已切换为摘要分页。导出与业务明确要求全文的接口不属于目录加载。发布顺序必须先部署提供新接口的 Go 后端，再发布调用它的桌面端。

## 可复现方法

后端执行 `python3 scripts/tiny-note-e2e.py --skip-crash-recovery --performance`。脚本仅使用本次创建的隔离 MySQL/Redis/MinIO，在专用知识库中插入千篇、万篇固定语料，每篇三份正文约 7 KB，带相同更新时间和交错置顶；不读取或修改真实笔记。此参数保留 API/并发验收，只跳过此前已经验证的崩溃场景。

每组读取旧全量接口一次作为实际响应基线，再测量 12 次摘要页请求，并完整遍历所有分页验证总数、顺序与去重。额外验证深层正文搜索、标签/排除标签、笔记本、回收站、详情、用户隔离、游标作用域及大小上限。

## 已接入界面

## 主目录与正文缓存（2026-09-06）

主目录首次读取 80 条摘要和笔记本元信息；展开笔记本按需读取独立页，计数采用服务端聚合，最近删除也独立分页。首页/对话引用、知识库笔记和图片插入选择器使用各自的搜索/分页状态，不再依赖完整正文列表。搜索由后端覆盖正文，图片追加前按 ID 获取完整 Note。

正文与摘要分开存储。只向编辑器传完整 Note，保存前校验三份正文类型；重命名只提交标题与版本。正文缓存采用 20 篇 / 64 MiB（按 UTF-16 字符估算）的软预算，淘汰已保存且非当前打开的正文，保护未解析源码草稿及未保存修改。单篇超限或大量未保存草稿可超过预算，这不是整个 WebView 的内存上限。编辑器保存签名也使用弱引用，避免已淘汰正文仍被签名副本保留。账号重置后拒绝旧详情响应。

切换笔记前先保存当前编辑器。保存失败停止切换；详情读取失败保留旧编辑器并提供重试；并行点击只接受最后一次选择；保存等待期间继续输入，不会将新草稿误标为已保存。深链不依赖首批摘要中是否有该 ID。分页不是快照，跨客户端编辑导致位置变化时仍需刷新目录。

浏览器隔离 225 篇样例实测：

- 笔记本 80 → 160 → 225 加载，正文缓存始终为 1。
- 搜索摘要 200 字之外的关键词找到第 225 篇，打开后正文缓存为 2。
- 连续打开 25 篇后正文缓存为 20；Markdown 输入后立即切换并返回，新增内容完整保留。
- 单元测试覆盖脏缓存、未解析源码保护、请求去重、版本刷新、账号重置、摘要保存拒绝、保存失败停止切换、响应乱序及深链失败重试。
