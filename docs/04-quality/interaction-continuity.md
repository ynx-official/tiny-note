# 启动与笔记加载连续性

状态：Review。最后更新：2026-09-14。

关联：[设计系统](../02-design/design-system.md)、[目录与正文缓存](note-library-performance.md)、[启动性能历史记录](startup-performance-and-typescript.md)。

## 已确认范围

用户确认处理启动、打开文章和打开笔记本时的闪烁。继续沿用 Friday 外壳和 Notion 补充规范，优化加载状态、阅读位置恢复和目录复用；业务 API、保存规则与云端存储边界不变。

## 实现规则

- 启动页使用静态外壳，移除完成提示及固定 360ms 等待。首页内容和输入框始终挂载，登录及模型初始化只限制相关操作，不丢弃初始化期间输入的草稿。
- HTML head 在加载样式及绘制正文前解析设备主题；手动主题优先，system 使用当次系统主题。新增内联脚本保持精确 CSP 哈希授权。设置读取失败保留已有主题；模型请求不延迟已返回设置的应用。
- 文章读取保留当前编辑器，超过 200ms 才显示不占布局空间的状态提示。详情失败保留当前正文及重试入口；首次目录未完成时不显示“暂无笔记”。
- 正文渲染完成立即恢复阅读位置；关联笔记异步读取，过时响应丢弃。关联区域预留一行紧凑空间，晚到的链接不改变正文视口高度。正文状态不等待所属笔记本分页完成。
- 同一筛选刷新保留上次成功的条目、数量和游标，成功后一次更新；切换筛选先移除旧筛选结果，防止将它们误呈现为新结果。失败重试保留原请求类型，区分刷新首页与追加下一页。
- 笔记侧栏展开、折叠、滚动、外部来源及回收站状态存放在当前账号的 Pinia 内存中，退出时重置。返回页面在目录读取成功后的 30 秒内复用目录，超时在现有视图上刷新；显式刷新和业务修改仍执行实际请求。
- 模板、标签元信息和既有过期回收站维护不阻塞文章打开。目录请求及异步元信息检查账号作用域，旧请求不能污染重置后的状态。

200ms 提示阈值与 30 秒复用窗口是本次实现参数，不是服务端 SLA，也不构成离线模式或新的持久化正文缓存。

## 验证

回归先复现再修复，覆盖：刷新期间保留数据、筛选隔离、失败重试页型、慢请求提示时机、编辑器保持挂载、阅读位置不等待关联请求、返回时展开状态与回收站恢复、非必要数据不阻塞文章，以及账号重置后的请求隔离。

2026-09-14 使用隔离的浏览器测试适配器、85 篇样例文章和 800ms 人工请求延迟进行界面检查：

- 1280×800：文章切换和目录刷新期间，正文视口顶部始终为 145px、高度始终为 649px；旧编辑器节点保持不变。旧文章保留到新正文到达，状态提示延后出现，阅读位置在正文切换时恢复，关联响应返回后无第二次滚动。
- 目录刷新期间总数持续为 85，没有清空后归零。返回笔记页前后侧栏 scrollTop 均为 1459px，展开状态保留。
- 1280×800 亮色和 1024×700 深色界面无整页横向溢出；本次浏览器检查未记录到控制台错误。

这些是浏览器隔离样例结果，不能代替真实网络、长图文/大型 Mermaid 或安装版 WebView2 冷启动测量。Tauri 原生窗口在网页首次绘制前仍使用配置中的背景色；本次没有宣称消除该系统阶段的闪色或重新通过历史冷启动时间指标。

最终 `npm run check` 通过：92 个测试文件、398 个用例通过；lint、typecheck、contracts、components、styles 和生产 build 全部通过。启动资源预算为 JS 174,292B / 500,000B、CSS 71,284B / 100,000B。构建仍提示编辑器等部分按需加载包超过 500KB；该提示不等于首屏预算超限。
