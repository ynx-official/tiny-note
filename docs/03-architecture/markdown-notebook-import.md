# Markdown 笔记本导入设计

状态：Approved。最后更新：2026-09-14。

关联文档：[业务规则](../01-requirements/business-rules.md)、[MVP 验收标准](../01-requirements/acceptance/mvp.md)、[命令与接口契约](api-contracts.md)、[威胁模型](threat-model.md)。

## 目标

用户选择一个本机目录后，Tiny Note 将其中的 `.md` 和 `.markdown` 文件导入当前账户的云端笔记空间，并把有效目录层级转换为笔记本树。导入不会修改或删除源目录，也不会把导入后的笔记继续绑定到源文件。

本功能与“外部来源 → 打开文件夹”语义不同：外部来源保持本机文件绑定且不进入普通笔记树；Markdown 笔记本导入创建独立云端副本并进入普通笔记树。

## 已确认规则

- 用户选择的根目录只要自身或任意后代存在 Markdown，就创建为根笔记本。
- 目录自身没有 Markdown、但后代存在 Markdown 时，保留该目录，以维持完整相对路径。
- 某目录整棵子树都没有 Markdown 时，不创建该目录对应的笔记本。例如只包含图片或 PDF 的 `attachments` 目录会被整体忽略。
- 支持 `.md` 和 `.markdown`，扩展名匹配不区分大小写。
- 每个 Markdown 文件创建一篇普通云端笔记；标题取不含扩展名的文件名，`contentMarkdown` 保留读取到的原文。
- 导入不覆盖、修改或删除任何已有笔记本、笔记或源文件。

## 首版约束

- 不导入 `.txt`、图片、PDF、Office 文件或其他附件。
- 不改写 Markdown 中的相对链接。指向未导入附件的链接可能无法在云端笔记中显示。
- 不跟随目录符号链接或文件符号链接，避免循环扫描、重复导入和越过用户选择的目录。
- 单文件沿用外部 Markdown 的 10 MiB 上限；一次导入最多 1000 篇、正文总量最多 50 MiB。超过任一限制时只显示扫描结果和错误，不允许提交。
- 首版只在 Tauri 桌面环境提供目录导入。浏览器模式保留现有多文件导入，不模拟目录授权。

这些限制属于首版设计选择，不是源格式能力承诺。后续若需要附件迁移、超大仓库分批续传或浏览器目录导入，应独立设计。

## 用户流程

1. 用户从笔记侧栏的新建菜单选择“导入 Markdown 笔记本”。
2. 系统文件夹选择器返回一个本机目录；取消选择时不显示错误。
3. Rust 只读扫描目录并返回导入清单。前端显示根笔记本名称、笔记本数量、笔记数量、被忽略目录数量和读取错误。
4. 若没有 Markdown，界面提示“所选文件夹没有 Markdown 文件”，不显示确认操作，也不创建云端数据。
5. 若存在读取错误或超过限制，预览明确列出原因并禁用“开始导入”。用户可取消并修复源目录后重试。
6. 用户确认后，前端一次提交规范化清单。导入期间禁用重复提交，并显示确定性进行中状态。
7. 服务端事务成功后，前端刷新笔记本与摘要目录，展开新建根笔记本，并打开按规范相对路径排序后的第一篇笔记。
8. 失败时显示服务端错误，当前笔记树保持不变；用户可使用同一预览重新提交。

预览对话框遵循项目已记录的 Friday 外壳与 Notion 补充规范：使用紧凑信息行、明确错误状态和标准确认按钮，不引入新的视觉体系。

## 目录映射

扫描阶段先收集所有有效 Markdown 文件，再由每个文件的相对父目录反向标记需要保留的目录。未被任何文件路径引用的目录被裁剪。

例如：

```text
My Notes/
├─ README.md
├─ work/
│  └─ plan.md
├─ archive/
│  └─ 2025/
│     └─ summary.markdown
└─ attachments/
   ├─ cover.png
   └─ demo.pdf
```

生成：

```text
My Notes
├─ README
├─ work
│  └─ plan
└─ archive
   └─ 2025
      └─ summary
```

目录与文件按规范化相对路径稳定排序，使预览、请求和测试结果可重复。相对路径只能使用普通路径段；空段、`.`、`..`、绝对路径和根前缀均被拒绝。

## 同名策略

导入始终创建一棵新的根笔记本树，不复用现有同名笔记本。若当前用户根级已有同名笔记本，服务端为新根节点追加 ` (2)`、` (3)` 等最小可用序号。

一次导入内，同一父目录下的笔记本名称和笔记标题分别保证唯一。发生名称冲突时使用相同的递增后缀规则。比较应采用数据库与产品统一的大小写规则，最终名称由服务端决定，前端预览标记可能发生冲突改名，但不把预览名称当作权威结果。

## 组件边界

### Tauri 桌面层

新增独立平台命令，例如 `markdown_notebook_pick_folder`。它负责：

- 调用系统目录选择器；
- 规范化所选根目录；
- 在根目录内做一次只读递归扫描；
- 拒绝符号链接和非普通文件；
- 校验扩展名、单文件大小、文件数和总大小；
- 读取 UTF-8 Markdown，并返回根目录名、相对路径、正文、大小及扫描错误。

该命令不创建笔记本或笔记，不持久化目录授权，也不把文件加入“外部来源”历史。Rust 扫描结果不返回绝对路径给服务端；前端仅在本轮预览中持有源路径相关信息。

### Vue 前端

前端新增导入编排服务和预览对话框。编排服务把 Rust 清单转换为类型化业务请求，并复用现有 `markdownToEditorHtml`、`sanitizeEditorHtml` 与 `textFromEditorHtml` 生成笔记的三种正文表示；Pinia store 只负责提交导入、接收结果和刷新目录，不实现目录裁剪或服务端命名规则。

`CommandMap` 新增一个平台命令和一个业务命令。`tauri.ts` 将目录选择命令归类为平台能力，将批量导入命令经 `remoteCommands.ts` 发往 Go 服务端。测试用 `browserBackend` 提供确定性的内存实现，但生产浏览器模式不展示目录导入入口。

### Go 服务端

新增 `POST /notes/import-markdown`。请求包含根目录名称和 Markdown 文件数组，每项只包含规范化相对路径与正文。服务端重新校验数量、总字节数、路径、扩展名、名称长度和当前用户身份，不能信任桌面扫描结果。

服务端在单个数据库事务中：

1. 锁定或以一致性查询读取当前用户相关名称；
2. 计算根笔记本最终名称；
3. 按深度从浅到深创建有效笔记本；
4. 校验三种正文表示并批量创建笔记；
5. 创建完成后统一重建该用户的笔记链接；
6. 返回新根笔记本、创建数量、最终名称映射和第一篇笔记 ID。

任一步骤失败都回滚本批创建。接口不得调用逐篇 `CreateNote`，避免每篇笔记重复重建全部双向链接。

现有 `tn_notebooks` 和 `tn_notes` 已能表达导入结果，不需要数据库迁移。

## 接口草案

请求：

```json
{
  "rootName": "My Notes",
  "files": [
    {
      "relativePath": "README.md",
      "contentMarkdown": "# Readme",
      "contentHtml": "<h1>Readme</h1>",
      "contentText": "Readme"
    },
    {
      "relativePath": "work/plan.md",
      "contentMarkdown": "# Plan",
      "contentHtml": "<h1>Plan</h1>",
      "contentText": "Plan"
    }
  ]
}
```

成功结果：

```json
{
  "rootNotebookId": "uuid",
  "rootNotebookName": "My Notes (2)",
  "notebookCount": 2,
  "noteCount": 2,
  "firstNoteId": "uuid",
  "renamed": []
}
```

服务端使用稳定业务错误标识区分空清单、非法路径、超限、非法 UTF-8 和事务失败；HTTP 与统一响应格式沿用现有 Tiny Note 约定。重试同一个请求会再次创建一棵带新后缀的树，因此前端必须阻止双击和并发重复提交。首版不新增持久化幂等键。

## 错误与恢复

- 选择取消：安静返回，不创建数据。
- 没有 Markdown：信息提示，不创建数据。
- 单文件读取失败或非法 UTF-8：预览列出相对路径，禁止提交。
- 文件数、单文件或总量超限：预览显示实际值和限制，禁止提交。
- 网络、认证或服务端校验失败：保留预览，允许用户重新提交；401 仍执行现有登录失效流程。
- 事务失败：服务端回滚全部新记录，前端不局部刷新为成功状态。
- 导入成功但目录刷新失败：结果本身已提交成功，前端提示刷新失败并允许重新加载；不能自动再次提交导入。

## 安全边界

- Rust 只读取用户通过系统选择器授权的根目录，不跟随符号链接。
- 绝对本机路径不发送给服务端，不写入笔记正文、日志或审计摘要。
- Markdown、HTML 和纯文本均作为不可信输入处理。前端生成 HTML 时复用现有清洗规则，后续显示时仍执行既有 DOM 清洗，脚本、事件属性和危险 URL 不进入可执行 DOM；服务端不执行或渲染传入 HTML。
- 服务端逐项校验相对路径，拒绝路径穿越、控制字符、非法空名称和超长名称。
- 批量写入必须绑定当前登录用户；请求中的任何标识都不能指定其他用户的笔记本。
- 审计记录只保留导入数量、结果和新根笔记本 ID，不记录正文或源路径。

## 验证计划

Rust 单元测试覆盖扩展名大小写、稳定排序、空目录、纯附件子树、只有后代含 Markdown 的父目录、符号链接、非法 UTF-8、读取错误和三类容量限制。

前端测试覆盖入口可见性、取消、空目录提示、预览统计、错误禁用、重复点击保护、请求映射、成功刷新与选中、失败后保留预览，以及浏览器模式隐藏入口。命令契约检查必须识别新增平台命令和业务命令。

Go 单元与 MySQL 集成测试覆盖完整层级、父级保留、空清单拒绝、同名后缀、所有权隔离、路径穿越、容量限制、三种正文表示校验、单次链接重建和中途失败整批回滚。

实现完成后运行前端相关单测、`lint`、`typecheck`、命令/组件/样式检查与构建；运行 Rust 格式化检查、单测和 Clippy；运行 Go 格式化、相关测试、全量 `go test ./...` 与 `go vet ./...`。最后使用桌面应用实际导入包含嵌套目录和 `attachments` 的样例目录，检查预览、笔记树和正文。

## 计划改动范围

Tiny Note 客户端预计涉及：

- `src-tauri/src/lib.rs`：目录扫描 DTO、平台命令和 Rust 测试；
- `src/services/commandMap.ts`、`src/services/tauri.ts`、`src/services/remoteCommands.ts`：类型化命令和路由；
- `src/components/notes/NotesSidebar.vue`、`src/composables/useNotesWorkspace.ts`、`src/stores/notes.ts`：入口、编排、提交与刷新；
- 新增独立导入预览组件及其测试；
- `src/services/browserBackend`：测试适配；
- 相关需求、契约、安全和质量文档。

Go 服务端预计涉及：

- `api/tinynote`：批量导入请求定义；
- `internal/modules/tinynote/controller`、`service`、`logic`、`model/bo`：接口分层和事务实现；
- 组装契约测试、逻辑单测和 MySQL 集成测试；
- Tiny Note API 与交付文档。

不修改现有数据库结构，不改变外部 Markdown 打开和写回规则，不导入附件，不执行生产迁移或发布。
