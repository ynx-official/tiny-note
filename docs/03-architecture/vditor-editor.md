## 决策与边界

用户明确要求两个文章模式全部切换到 Vditor，Markdown 兼容优先。`NoteEditor` 只挂载一个 `VditorEditor`，即时编辑映射 IR，Markdown 映射 SV；预览由同一实例生成。保留 Friday 外壳、独立名称输入、自动保存和 CommandMap。没有生产数据迁移，不修改 Go/Rust 业务边界。

旧 TipTap/CodeMirror 组件、扩展及其历史测试仍保留在源码中，避免删除工作区已有改动；文章运行路径不再引用这些编辑器。后续删除这些历史文件与依赖可单独进行。

## 正文与保存

2026-09-30 先按用户反馈移除正文上的 `note-prose`、容器上的 `editor-content`，隔离旧排版；随后用户确认效果图方向，采用 Vditor 专用应用主题。`vditor-editor.css` 集中处理容器、分栏、应用自有浮层及作用域内的字体/色彩/间距。仅对上游写入行内样式的工具栏与 IR 根节点 padding 使用定向覆盖，不改源码标记的 display/height/overflow。分隔条按实际工具栏高度定位，兼容换行。IR 聚焦代码时仍使用原生源码展开行为。

Mermaid 共用 `mermaidRenderer` 的明暗配色。渲染适配器在 WeakMap 中保留预览节点的原始代码，切换主题时仅重绘这些预览块；不得对整个编辑器调用图表渲染，否则会误处理带相同 language 类的可编辑源码。WeakMap 随预览节点移除释放，不在笔记或 DOM 中持久化缓存。

- `contentMarkdown` 为权威；HTML/纯文本是 Lute 派生缓存。HTML-only 旧笔记仅在内存转换，打开不触发保存。
- 包装层保留原始源文与 Vditor 规范化文本两份基准，单纯打开/切换不改写原文。实际输入遵循 Lute 的 Markdown 序列化，包括空白规范化。
- 输入先更新草稿，150ms 合并派生缓存，然后沿用 800ms 自动保存。主动保存、导出、切换文章或卸载前同步读取原生编辑内容。
- 切换文章先提交旧文章的内存正文，保存请求独立于新文章渲染；异步结果按原文章对象和 ID 归属，不能写入后打开的文章。
- 独立名称不从首行推导；目录覆盖正文 H1–H6，并跳转原生 IR、SV 或预览滚动区域。

## AI 适配

DOM 选区在克隆节点中插入临时定位标记，再由 Lute 序列化；使用 diff 映射回权威源文偏移，不修改实时 DOM 或撤销栈。任务请求只发送 `{from,to,text}`，不发送本地选区快照字段。

润色、扩写、翻译、总结、自定义指令和助理继续使用 `note_ai_task_create` 与现有任务中心。发送前保存文章，读取保存后的版本；等待期间切换文章或更改源文会中止该次前端提交。任务事件按当前请求 ID 接收。

建议使用原文/结果对照面板。`replace` 修改明确选区，无选区才替换全文；`insert` 放在选区后或可靠光标位置。加载外部提案时若本地有未保存修改，将该提案标记为过期；应用前校验源文快照、选中文字、范围和 `baseUpdatedAt`，再调用 `note_edit_apply`。旧 ProseMirror 坐标只在原文存在唯一精确匹配时恢复，否则要求重新生成。服务端失败或缺少确认结果恢复草稿，保留建议供重试。

FIM 继续沿用已有流接口和开启开关，要求已有上下文授权；结果绑定文章、源文与光标，Tab 接受，Esc 关闭。外部文件继续禁止直接调用云端笔记 AI，需先导入。

## 运行资源

剪贴板中的图片文件（含截图）在 IR/SV 两种模式中共用上述上传与 Base64 回退逻辑；在原生粘贴处理前捕获图片，不改变普通文本粘贴。切换笔记或卸载编辑器后丢弃待插入结果。

本地图片插入优先通过现有 `/auth/file/upload/img` 接口上传（multipart `file` 字段），成功时使用返回的 HTTP(S) `fileUrl`。网络、业务错误或无效 URL 时才读取为 Base64；沿用 5 MB 限制。异步结束后核对原笔记与编辑器，避免切换笔记后误插入。此规则由用户于 2026-09-30 确认。

锁定 Vditor 3.11.2。`predev` / `prebuild` 将运行时脚本、样式和字体复制到 `/vendor/vditor/dist`，生成资源不进入 Git。Lute、中文语言和图标在实例创建前加载，失败显示重试入口；卸载重建可重新加载被原生销毁逻辑移除的图标资源。

Mermaid 复用项目 11.17.1，并强制 strict 模式。PlantUML 编码适配器明确拒绝远程渲染，防止上游默认将图表源码放入公共服务 URL。HTML 派生内容继续经过项目净化器，Tauri CSP 保持不变。
