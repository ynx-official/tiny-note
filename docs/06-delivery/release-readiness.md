# 发布前验收

更新：2026-09-06。当前处于迁移稳定性阶段，尚不满足正式发布条件。以下记录针对当前工作区，旧版安装或旧提交的 CI 结果不能替代。

## 工作流入口

- `Tiny Note CI`：PR、main 推送、手动触发及其他工作流复用，执行发布资料、前端全部门禁及 Linux Rust fmt/test/clippy。
- `Release Tiny Note`：先检查资料，再复用上述 CI；通过后执行 Windows x64、Linux x64、Intel Mac、Apple Silicon Mac 打包，各平台继续执行原生 fmt/test/clippy。
- 手动触发 `Release Tiny Note` 仅构建、测试和保留工作流 artifacts，**不会发布 Release 或更新清单**。可在验收分支验证四平台构建。
- 只有推送 `tiny-note-v*` 标签才进入现有 Release 上传与更新清单发布步骤。推送标签前必须完成下列安装升级验收，并确定新版本及发布资料；当前 `0.1.14` 资料描述已存在版本，不能代表这些未发布的迁移改动。
- 后端仓库 `Tiny Note service checks` 独立运行 Go test/vet/race、隔离真实 API、双实例恢复、并发和千篇/万篇基准。桌面仓库的绿灯不代表另一个仓库的后端门禁通过；发布记录应同时引用两边的提交和工作流结果。

## 每个平台应保留的实际证据

1. 记录系统版本、CPU 架构、前后端提交、安装包 SHA-256、工作流链接和测试账户所连接的隔离后端。
2. 在干净用户环境安装并启动，验证窗口/托盘、登录、笔记读写、退出重启，以及 Markdown 文件关联和已有实例转发。
3. 从上一正式版本安装开始，用隔离账号和测试文档操作一次检查更新、下载、安装及重启；确认应用版本、账户/设置和外部文件历史保留。旧 SQLite 不读取、不迁移、不删除。
4. 原生打开 UTF-8 BOM/CRLF 外部 Markdown，保存并逐字节检查换行/BOM；另一个程序修改源文件后，应用保存必须拒绝覆盖。确认仅显式导入创建云端副本。
5. 在实际 WebView 中检查知识库文本、图片、多页 PDF、缩放及原文件下载，保留落盘文件和与原文件一致的摘要；仅出现“下载成功”提示不足以判定通过。
6. 千篇/万篇目录执行打开、搜索、连续编辑切换和分页，记录用户操作延迟、进程内存及是否丢失未保存内容。接口基准不能替代此项。

这些操作只使用隔离测试数据。旧版已上传的外部文件副本仍需另行核对归属与清理边界，不自动删除。任一必需项缺少证据时，继续保留为未完成。
